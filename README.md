# LunaPet

一个桌面宠物引擎。角色在桌面上走来走去、起步和收工会转身、能被拖着甩、松手会掉下来、落地会回正，点多了还会自己朝你的光标走，没人理她久了会自己睡下。

引擎是自研的，**不基于 DyberPet**。依赖只有 PySide6 和 numpy。

> ⚠️ **仓库里没有角色素材。**
> `packs/` 下面的每一帧都是角色资产，不随代码发布 —— 这里面也没有。
> 想跑起来得自己做一份角色包：格式见 [docs/PACK_FORMAT.md](docs/PACK_FORMAT.md)，
> 起手直接把 `packs/_template/pet.json` 复制过去改。

---

## 为什么单独分一层

`pet_engine/core.py` 是**纯逻辑**，一行 UI 代码都没有，也不 import PySide6。
状态机、物理、屏幕限位、拖拽手感全在这一层 —— 因为只有它能够无头测试（`_自测_core.py` 就是这么跑的）。

`pet_engine/ui.py` 只管窗口、绘制、鼠标、定时器，不判断任何业务。

分开的收益很实在：**将来换壳（Godot / Electron / 别的）只需要重写 ui.py，素材和参数一个字不动。**

| 文件 | 干什么 |
|---|---|
| `run.py` | 启动入口（`--preset 轻/中/重` 试手感，`--tuner` 开调试台）|
| `pet_engine/core.py` | 逻辑层：角色包加载 / 动作状态机 / 转身接线 / 睡眠周期 / 阻尼单摆 / 屏幕边界 |
| `pet_engine/ui.py` | 渲染层：窗口 / 逐动作画布与锚点 / 绘制 / 鼠标 / 托盘 |
| `pet_engine/console.py` | 手感调试台（滑杆实时生效 + 预设存取 + A/B 秒切 + 睡眠演示按钮）|
| `pet_launcher.py` | 打包专用入口，只做路径决策，渲染与逻辑一行不改 |

## 跑起来

```bash
pip install -r requirements.txt

python run.py <你的角色包目录>     # 例：python run.py packs/mycat
python run.py <包> --preset 重     # 试手感：轻 / 中 / 重
python run.py <包> --tuner         # 开调试台，边拖边看参数效果
```

操作就三条：**左键拖拽**（有倾斜，有惯性），**松手**（下落、落地、回正），**点一下**（摸她；睡着时是叫醒）。托盘图标切换显示和退出。

## 几个设计决定，值得单独说

### ① 拖拽手感用阻尼单摆，不是插值公式

```
θ'' = −ω0²·sinθ − 2ζω0·θ' + F(鼠标速度)
```

鼠标速度是力，重力把它拉回，ζ<1 所以会晃过头 —— 那个"惯性感"就是从这来的。

麻烦的地方在于 `tilt_omega0`（回正快慢）、`tilt_zeta`（晃不晃）、`tilt_drive`（甩多猛才倾）**三个参数是耦合的**，光看公式推不出好看的手感。所以配了三档预设，外加一个滑杆调试台 —— ⛔ 别靠猜，拧出来。

### ② 走路不许太空步，这件事在格式层面解决

DyberPet 的动作配置里只有 `frame_move`（每帧位移）。它没有推导依据，所以只能手调，试窄了永远搜不到正确周期。

这里的 `pet.json` 要求填两个字段：

| 字段 | 含义 |
|---|---|
| `cycle_frames` | 一个完整循环跨多少帧（走路的两步就填这里）|
| `stride_px` | 一个循环前进多少像素 |

引擎自己算 `move_per_frame = stride_px / cycle_frames`。**填进去的就是"两步走多远"，不需要反推。**

### ③ 睡觉这件事，麻烦全在"醒来"那三段上

睡着本身很好写：连续待机满 `sleep_after` 秒就进 `sleep_in`，播完接 `sleep_loop` 循环。真正难的是叫醒。

第一版是 `sleep_out` 播完直接回 `idle`。跑出来一眼就看出问题：`sleep_out` 的末帧是趴着的，`idle` 的起帧是站着的，中间那一下是**硬切**，像幻灯片翻页。人从睡到醒本来就有个过程 —— 撑起来、舒展、然后才站定。

所以叫醒走三段：`sleep_out` → 舒展动作 → `idle`。舒展优先用 `stretch`，没有这个素材就退到 `land_settle`（落地收尾），两个都没有就直接回 `idle`。**降级路径是必须的**——角色包里缺哪个动作都不该让程序崩掉，这一点在 `_自测_睡眠.py` 里是硬性检查项。

叫醒的触发口有三个，走的是同一个 `wake(reason)`：

| 触发 | reason | 说明 |
|---|---|---|
| 点她一下 | `click` | 睡着时点一下=叫醒，不播 `pat`，但**照样加好感、照样冒爱心** |
| 光标靠到 `wake_radius` 以内 | `cursor` | 只用横向距离算，不判断上下 |
| 调试台按钮 | `console` | 见下面「自测」 |

被拎起来（`begin_drag`）是**只清状态不起床链**的第四种情况：直接作废睡眠计时和 `asleep` 标志，因为拖拽有自己的动作序列，不能让它和起床动画抢。

还有一个细节值得记一笔：睡着时好感度衰减乘 `sleep_mood_decay_scale`（默认 0.2）。不然挂机一晚上，她睡醒发现自己好感度掉光了 —— 这个设定说不过去。

### ④ 一个角色，可以有几套画布尺寸

趴姿是横躺的。用原来那套 2:3 的竖幅画布，她睡着的样子会被挤成一小团，两边空一大片。所以现在每个动作可以自己声明 `canvas` 和 `anchor`：

```json
"sleep_loop": { "frames": 24, "fps": 10.0, "loop": "pingpong",
                "canvas": [520, 536],
                "anchor": [240, 518] }
```

不写的动作回落顶层 `canvas` / `anchor`，所以原来那 9 个动作一行都不用改。`anchor` 的语义也跟着从"脚底中点"放宽成"贴地参考点" —— 站姿是脚底中点，侧躺是身体下缘中点，都是"挨着地面那个点"。

麻烦出在轮廓上。屏幕限位是按角色实际的 alpha 轮廓算的，原来是拿**所有动作的并集**算一份。横躺的趴姿比站姿宽一倍多，并集会把她站着的限位框撑到屏幕外 —— 站姿也能走出屏了。所以轮廓也得逐动作算，切动作时换用对应那份。

真正让我返工两次的是切换的那一帧：`setFixedSize` 是**异步**生效的（Qt 要重排窗口），而 `move()` 是立刻的。按「推进物理 → 换尺寸 → 定位」这个顺序走，切换帧会出现"旧尺寸的窗口 + 新 anchor 的位置"，肉眼就是**闪一下**。最后改成：换完尺寸先强制同步布局，并且**这一帧干脆不画**，下一帧尺寸稳了再正常画。宁可少画一帧，也不能画一帧错的。

### ⑤ 转身，和它捅出来的一个坑

`turn_in` 有 18 帧，但前 9 帧几乎没动 —— 相邻帧差异率 0.02% ~ 2.4%，第 9 帧起才真的转（11% → 22%）。整段播完再起步，等于她决定要走之后**先愣一下**才动身。所以 `pet.json` 里给 `turn_in` 写了 `"start": 9`，只播转身那一段。没配 `start` 的动作不受影响。

走路收尾同理。之前走到目标点直接 `play("idle")`，可她是**侧着身子**走到的，一帧之内变正面 —— 那一下比缺动作还难看。现在走完先 `turn_out` 转回正面再回 `idle`。`turn_in` / `walk` / `turn_out` 三段共用同一个朝向标志决定要不要镜像，接缝才不会硬切。

然后是坑。为了不让转身被"目标导向走路"每帧顶掉，我把 `turn_in`/`turn_out` 从目标驱动里排除了；同时立了条规矩：**目标还没走到，走路计时到点也继续走，不许中途停下转身**（否则就是"转身回正面 → 马上又侧身继续走"反复横跳）。

规矩本身没错，但它把一个**原本能自愈的小毛病**变成了不治的。`_pick_goal` 挑目标写死 ±80px 边距，可 walk 的轮廓左右各占 174 / 151px —— 目标一旦落在 `[屏幕左+80, 屏幕左+174)` 这条窄带里，她**永远走不到**：判据是 `|goal_x − body.x| <= arrive_eps`，被墙挡住就永远为假。以前走完计时会回 `idle` 重挑目标，自己就爬出来了；现在"有目标就不许停"，她就**贴着墙原地走**，一直走到 40~90 秒后按睡眠计时睡着才算解脱。

修法是别去预测"够不够得到"，直接看结果：这一帧她被屏幕限位挪动了、而目标还在被挡住的那一侧 —— 那就认作到站，清目标、转身、回 `idle`。这样不用知道各动作的轮廓，光标跑到屏幕外（`seek` 目标）也一并管住了。

### ⑥ 点一下 ≠ 拖一下

这两个动作的判定必须彻底分开，否则会互相吃掉。

旧写法是 `mousePressEvent` 里无条件 `begin_drag()`。后果是：睡着时点她一下，`begin_drag` 已经把 `asleep` 清成 `False`、`state` 也变成 `drag` 了，等松手判定为"点击"再调 `on_click()`，唤醒那个分支**永远进不去** —— 表现就是她直接瞬移回站立姿势，`sleep_out` 一帧都没播。现在改成移动超过 `DRAG_THRESHOLD`（6px）才真正 `begin_drag`，按着不动就只算"按着"。

另外"光标靠近就吵醒她"这条，原来只在 `mouseMoveEvent` 里喂光标位置 —— 而那个事件**只有鼠标进到窗口上**才触发。于是她旁边 120px 内飘着的光标，`core` 根本收不到坐标，永远吵不醒。现在直接问 Qt 要全局光标位置，鼠标在桌面任何地方她都知道。

## 自测

```bash
python _自测_core.py       # 无头，纯逻辑：状态机 / 物理 / 边界 / 步幅
python _自测_互动.py       # 合成真实鼠标事件，验证"点她真的有反应"
python _自测_手感.py       # 量化三档预设的峰值角度 / 滞后 / 回正时间
python _自测_睡眠.py       # 睡眠状态机：入睡 / 三种叫醒 / 睡着时要保持不动
python _自测_GUI睡眠.py    # 离屏起真窗口，QTest 点调试台的睡眠按钮
python _自测_点击唤醒.py   # 睡着时"点一下"和"拖一下"必须走两条不同的路
python _自测_转身接线.py   # 转身三段接线 + 够不到的目标不许贴墙原地走
python _自测_draghang.py   # 被拎起来：状态机 / pingpong / 倾角 / 松手
```

全部 `exit(非0)` 表示失败，可以直接挂 CI。要读 `packs/luna` 的那几个，**克隆下来直接跑会报"角色包不存在"** —— 指到你自己那份包就行。

`_自测_睡眠.py` 里有个地方是故意这么写的：验证叫醒链之前把 `sleep_after` 改成 600 秒。不这么干的话 8 秒的观测窗口里她又睡回去了，看到的状态序列会少一截。**测试脚本本身要是可读的**，别人看到这行得能立刻明白为什么。

`_自测_转身接线.py` 第 ⑧ 项 monkey-patch 了 `_pick_goal` 来把目标钉死在左边，**用完立刻还原**。这条注释是拿血换的：第一版忘了还原，后面第 ⑩ 项的"120 秒长跑"就拿着那个钉死的目标一直跑，目标恰好落在够不到的窄带里 —— ⑩ 挂掉，最后反而是它把 ⑤ 里那个真 bug 钓出来了。
