# 角色包格式

一个角色包就是一个目录，引擎只认两个东西：`pet.json` 和 `action/` 下的帧。

```
packs/mycat/
  pet.json              ← 全部参数
  action/
    idle_0.png          ← 帧号从 0 开始，不许跳号
    idle_1.png
    ...
    walk_0.png
    ...
```

帧命名规则：`action/<动作名>_<帧号>.png`（帧号补不补零都行，`core.PetPack.frame_path()` 里就是 `f"{action}_{idx}.png"`）。
必须 **PNG 带 alpha**，`idle_0` 到 `idle_{frames-1}` 一张都不能缺 —— 缺了引擎会跳过那张，动作就会缺帧抖动。

---

## pet.json 顶层

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | str | 显示用（也用于日志）|
| `canvas` | `[w, h]` | 单帧画布尺寸。**默认值**，动作可以各自覆盖（见下）|
| `anchor` | `[x, y]` | ⭐ 角色**贴地参考点**在画布里的坐标。窗口定位、落地、拖拽全以它为基准 |
| `scale` | float | 整体缩放（默认 1.0）|
| `actions` | object | 动作表，见下 |
| `behaviour` | object | 手感与互动参数，见下 |

`anchor` 是最容易搞错的一个。它不是画布中心，是**贴地参考点** —— 引擎把它对齐到窗口坐标，所以只要每帧的参考点位置一致，走路落地就不会上下跳。

站位动作的参考点就是**脚底中点**；但趴/躺类动作（比如 `sleep_loop`）躺着的时候没有"脚底"，那里填的是**身体下缘中点**。语义就一条：**挨着地面那个点**。

## actions

```json
"walk": {
  "frames": 28,
  "fps": 12.5,
  "loop": "cycle",
  "cycle_frames": 28,
  "stride_px": 154.0
}
```

| 字段 | 说明 |
|---|---|
| `frames` | 帧数（从 0 编号，必须连续）|
| `fps` | 播放帧率 |
| `loop` | `cycle` 循环 / `once` 播一次停住 / `pingpong` 来回 / `hold` 停在末帧 |
| `cycle_frames` | ⭐ 一个完整循环跨多少帧 |
| `stride_px` | ⭐ 一个循环前进多少像素 |
| `mirrorable` | 能否由本动作镜像出反向（左走），当前版本只做了读取 |
| `canvas` | ⭐ 本动作的画布尺寸，**不写就回落顶层 `canvas`** |
| `anchor` | ⭐ 本动作的贴地参考点，**不写就回落顶层 `anchor`** |
| `start` | ⭐ 起始帧，只对 `once` / `hold` 生效，**用来跳过素材开头的静止预备段** |

`pingpong` 的展开是 `0..n-1` 再接 `n-2..1`，首尾不去重。

### ⭐ 逐动作画布：趴姿不用挤在竖幅里

默认 `canvas` 是给站位动作定的（比如 512×512）。但趴/躺类动作是**横着**的，硬塞进竖幅会被挤成一小团、两边空一大片。所以动作可以自己声明：

```json
"sleep_loop": { "frames": 24, "fps": 10.0, "loop": "pingpong",
                "canvas": [520, 536],
                "anchor": [240, 518] }
```

⚠️ 两个必须一起改的连带项：

1. **`anchor` 也要跟着改** —— 画布尺寸一换，参考点的坐标就换了一套坐标系。
2. ⛔ **屏幕限位是按角色实际 alpha 轮廓算的，轮廓必须逐动作算。**
   要是拿"所有动作轮廓的并集"当一份用，横躺的趴姿会把站立时的限位框撑到屏幕外，
   站姿就能走出去。引擎内部已经是逐动作算的，你只管把 `canvas` / `anchor` 填对。

### ⭐ `start`：跳掉素材开头的静止预备段

有些 `once` 动作的素材开头有一段"准备"，画面几乎不动。整段播完再切换，观感就是**她决定动作之后先愣一下**。

实测数据（某 `turn_in` 素材，18 帧 @ 20fps）：

| 帧区间 | 相邻帧差异率 | 判断 |
|---|---|---|
| `#0 ~ #8` | 0.02% ~ 2.4% | 基本静止，是预备段 |
| `#9` 往后 | 11% → 22% | 真的在动 |

所以写 `"start": 9`，播放序列直接 `range(9, 18)` —— 少 9 帧，按 20fps 算就是起步**快了 0.45 秒**。

⛔ 别拿它当"裁剪工具"用 —— 它是播放起点，帧文件一张都不能删。

### ⭐ 为什么非要 `cycle_frames` 和 `stride_px`

走路最容易出的问题是**太空步**：脚在动，人却在滑。

根因是走路动画本身有周期 —— 比如 28 帧里走两步 —— 而位移必须跟这个周期对齐。只填"每帧位移"的话，这个对齐关系是**隐含**的，只能靠肉眼试，试窄了永远搜不到正确周期。

所以这里把两件事拆开填：

| 填什么 | 含义 | 怎么量 |
|---|---|---|
| `cycle_frames` | 两步跨多少帧 | 数动画本身，28 帧两步就是 28 |
| `stride_px` | 两步走多远 | ⭐ 量**支撑脚**每帧相对地面后退多少，乘上 `cycle_frames` |

引擎内部 `move_per_frame = stride_px / cycle_frames`，然后按播放进度推进角色位置。
**填进去的字面意思就是"两步走多远"，不需要反推。**

### 引擎会找哪些动作名

| 名字 | 什么时候播 | 缺失时 |
|---|---|---|
| `idle` | 待机。⭐ **唯一的兜底动作，必须有** | —— |
| `walk` | 自动走动 | 退回 `idle`，且不会走 |
| `drag` | 被拖着的时候 | —— |
| `fall` | 松手在空中 | —— |
| `land` | 落地那一下 | —— |
| `pat` | 被点击（摸摸） | 只加好感、冒爱心，不换动作 |
| `turn_in` | 起步转身（正面 → 侧身） | 跳过，直接 `walk` |
| `turn_out` | 收工转身（侧身 → 正面） | 跳过，直接回 `idle` |
| `sleep_in` | 入睡（`once`） | 直接进 `sleep_loop` |
| `sleep_loop` | 睡着之后的循环 | 退回 `idle`（等于不会睡） |
| `sleep_out` | 叫醒（`once`） | 跳过起床链，直接回 `idle` |
| `stretch` | 醒来后的舒展（`once`，按概率播） | 退到 `land_settle`，再没有就直接回 `idle` |
| `land_settle` | 落地收尾；也当 `stretch` 的兜底 | —— |

**凡是带「缺失时」那一列的，缺了都不会崩** —— 有一条降级链兜着。这一点在 `_自测_睡眠.py` 里是硬性检查项。

除了上面这些，`pet.json` 里还可以写任意动作名，引擎不会报错；但没人调它，就等于不会播。

## behaviour

### 走动节奏

| 字段 | 默认 | 说明 |
|---|---|---|
| `idle_duration` | `[3, 8]` | 待机持续多久（随机区间，秒）|
| `walk_duration` | `[4, 8]` | 一次走动持续多久（秒）|
| `walk_weight` | 0.6 | 待机结束后选择"走动"的概率 |
| `walk_speed` | 1.0 | 走速倍率，手感微调用 |
| `turn_chance` | 0.35 | ⭐ 换向概率。⛔ 给 1.0 会变成每帧翻面 = 闪烁 |
| `turn_ease_tau` | 0.35 | ⭐ 掉头缓动（秒）：换向时速度平滑过零，不是一帧掉头 |
| `gravity` | 1800 | 下落加速度（px/s²）|
| `screen_margin` | 0 | 距屏幕边缘留多少 |

### 拖拽手感（阻尼单摆）

```
θ'' = −ω0²·sinθ − 2ζω0·θ' + F(鼠标速度)
```

鼠标速度是力，重力拉回，ζ<1 → 欠阻尼 → 会晃过头。那个"惯性感"就是从这来的。

| 字段 | 默认 | 说明 |
|---|---|---|
| `tilt_omega0` | 5.0 | 固有频率：越大回正越快、越"轻" |
| `tilt_zeta` | 0.8 | 阻尼比：<1 欠阻尼（会晃），越大越快停 |
| `tilt_drive` | 14000.0 | 驱动力系数（鼠标速度到 v_ref 时的力）|
| `tilt_vref` | 1200.0 | 多大的鼠标速度算"快甩"（px/s）|
| `tilt_v_tau` | 0.05 | 鼠标速度低通（滤抖动）|
| `tilt_force_tau` | 0.12 | ⭐ 力的惯性：换向时"手"不会瞬移，越大越拖 |
| `tilt_drive_exp` | 3.0 | ⭐ 力的指数曲线：>1 → 慢移几乎不倾，快甩才猛涨 |
| `drag_tilt_max` | 45.0 | 倾角硬上限（度）|

⭐ 这四个参数（omega0 / zeta / drive / drive_exp）**是耦合的**，看公式推不出好看的手感。
所以 `run.py --tuner` 给了一个滑杆调试台，可以边拖边看、存预设、A/B 秒切 —— 别靠猜。

### 互动

| 字段 | 默认 | 说明 |
|---|---|---|
| `mood_max` | 100.0 | 好感度上限 |
| `mood_per_click` | 8.0 | 点一下加多少 |
| `mood_decay` | 1.2 | 每秒自然衰减 |
| `seek_cursor_mood` | 65.0 | 好感度高于这个值 → 会主动朝光标走 |
| `seek_chance` | 0.5 | 满足条件时"去找光标"的概率 |
| `arrive_eps` | 12.0 | 距目标多近算"到了"（px）|
| `pat_duration` | 1.2 | 被摸时播多久 `pat`（秒）|

### 睡眠

| 字段 | 默认 | 说明 |
|---|---|---|
| `sleep_after` | `[40, 90]` | ⭐ 连续待机多久入睡（随机区间，秒）|
| `sleep_mood_decay_scale` | 0.2 | 睡着时好感度衰减的倍率（挂机一夜不该掉光）|
| `wake_radius` | 120.0 | 光标横向进多少 px 会把她吵醒 |
| `stretch_chance` | 0.6 | 醒来后播 `stretch` 的概率 |
| `sleep_wakeup_need` | 1.0 | 摇几下才醒 —— ⛔ **预留字段，当前版本没接** |

完整链路：

```
待机满 sleep_after 秒
      ↓
  sleep_in (once) → sleep_loop (循环)
      ↓  叫醒：click / cursor / console
  sleep_out (once) → stretch (once, 概率决定) → idle
```

⛔ 睡眠计时**只在 `idle` 和 `walk` 里累加** —— 被摸、下落、转身都会把它清零。理由是"睡着了还在转身"说不通。

调试提示：默认要等 40~90 秒才睡，试的时候别干等 —— `run.py --tuner` 的调试台上有「😴 让她睡」「⏰ 叫醒」两个按钮。

## 最小可用包

只要一个动作也能跑起来：

```json
{
  "name": "mycat",
  "canvas": [512, 512],
  "anchor": [256, 512],
  "actions": { "idle": { "frames": 22, "fps": 10.0, "loop": "pingpong" } },
  "behaviour": {}
}
```

`behaviour` 缺失的字段全部有默认值（见 `core.Behaviour`），不用逐个填。

完整的字段清单可以照着 `packs/_template/pet.json` 抄。
