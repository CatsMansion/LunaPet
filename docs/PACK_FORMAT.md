# 角色包格式

一个角色包就是一个目录，引擎只认两个东西：`pet.json` 和 `action/` 下的帧。

```
packs/mycat/
  pet.json              ← 全部参数
  action/
    idle_0.png          ← 帧号从 0 开始，不许跳号
    idle_1.png
    ...
    walk_0.png
    ...
```

帧命名规则：`action/<动作名>_<帧号>.png`（帧号补不补零都行，`core.PetPack.frame_path()` 里就是 `f"{action}_{idx}.png"`）。
必须 **PNG 带 alpha**，`idle_0` 到 `idle_{frames-1}` 一张都不能缺 —— 缺了引擎会跳过那张，动作就会缺帧抖动。

---

## pet.json 顶层

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | str | 显示用（也用于日志）|
| `canvas` | `[w, h]` | 单帧画布尺寸。所有帧必须同尺寸，本引擎按 512×512 制作 |
| `anchor` | `[x, y]` | ⭐ 角色**脚底中点**在画布里的坐标。窗口定位、落地、拖拽全以它为基准 |
| `scale` | float | 整体缩放（默认 1.0）|
| `actions` | object | 动作表，见下 |
| `behaviour` | object | 手感与互动参数，见下 |

`anchor` 是最容易搞错的一个。它不是画布中心，是**脚底中点** —— 引擎把它对齐到窗口坐标，所以只要每帧的脚底位置一致，走路落地就不会上下跳。

---

## actions

```json
"walk": {
  "frames": 28,
  "fps": 12.5,
  "loop": "cycle",
  "cycle_frames": 28,
  "stride_px": 154.0
}
```

| 字段 | 说明 |
|---|---|
| `frames` | 帧数（从 0 编号，必须连续）|
| `fps` | 播放帧率 |
| `loop` | `cycle` 循环 / `once` 播一次停住 / `pingpong` 来回 / `hold` 停在末帧 |
| `cycle_frames` | ⭐ 一个完整循环跨多少帧 |
| `stride_px` | ⭐ 一个循环前进多少像素 |
| `mirrorable` | 能否由本动作镜像出反向（左走），当前版本只做了读取 |

`pingpong` 的展开是 `0..n-1` 再接 `n-2..1`，首尾不去重。

### ⭐ 为什么非要 `cycle_frames` 和 `stride_px`

走路最容易出的问题是**太空步**：脚在动，人却在滑。

根因是走路动画本身有周期 —— 比如 28 帧里走两步 —— 而位移必须跟这个周期对齐。只填"每帧位移"的话，这个对齐关系是**隐含**的，只能靠肉眼试，试窄了永远搜不到正确周期。

所以这里把两件事拆开填：

| 填什么 | 含义 | 怎么量 |
|---|---|---|
| `cycle_frames` | 两步跨多少帧 | 数动画本身，28 帧两步就是 28 |
| `stride_px` | 两步走多远 | ⭐ 量**支撑脚**每帧相对地面后退多少，乘上 `cycle_frames` |

引擎内部 `move_per_frame = stride_px / cycle_frames`，然后按播放进度推进角色位置。
**填进去的字面意思就是"两步走多远"，不需要反推。**

### 引擎会找哪些动作名

| 名字 | 什么时候播 |
|---|---|
| `idle` | 待机。⭐ **唯一的兜底动作，必须有** —— 其他动作缺失时都会退回它 |
| `walk` | 自动走动 |
| `drag` | 被拖着的时候 |
| `fall` | 松手在空中 |
| `land` | 落地那一下 |
| `pat` | 被点击（摸摸）|

找不到就退回 `idle`，不会崩。`pet.json` 里可以写别的动作名（比如 `sleep_in`），当前版本只是留着不报错，还没接进状态机。

## behaviour

### 走动节奏

| 字段 | 默认 | 说明 |
|---|---|---|
| `idle_duration` | `[3, 8]` | 待机持续多久（随机区间，秒）|
| `walk_duration` | `[4, 8]` | 一次走动持续多久（秒）|
| `walk_weight` | 0.6 | 待机结束后选择"走动"的概率 |
| `walk_speed` | 1.0 | 走速倍率，手感微调用 |
| `turn_chance` | 0.35 | ⭐ 换向概率。⛔ 给 1.0 会变成每帧翻面 = 闪烁 |
| `turn_ease_tau` | 0.35 | ⭐ 掉头缓动（秒）：换向时速度平滑过零，不是一帧掉头 |
| `gravity` | 1800 | 下落加速度（px/s²）|
| `screen_margin` | 0 | 距屏幕边缘留多少 |

### 拖拽手感（阻尼单摆）

```
θ'' = −ω0²·sinθ − 2ζω0·θ' + F(鼠标速度)
```

鼠标速度是力，重力拉回，ζ<1 → 欠阻尼 → 会晃过头。那个"惯性感"就是从这来的。

| 字段 | 默认 | 说明 |
|---|---|---|
| `tilt_omega0` | 5.0 | 固有频率：越大回正越快、越"轻" |
| `tilt_zeta` | 0.8 | 阻尼比：<1 欠阻尼（会晃），越大越快停 |
| `tilt_drive` | 14000.0 | 驱动力系数（鼠标速度到 v_ref 时的力）|
| `tilt_vref` | 1200.0 | 多大的鼠标速度算"快甩"（px/s）|
| `tilt_v_tau` | 0.05 | 鼠标速度低通（滤抖动）|
| `tilt_force_tau` | 0.12 | ⭐ 力的惯性：换向时"手"不会瞬移，越大越拖 |
| `tilt_drive_exp` | 3.0 | ⭐ 力的指数曲线：>1 → 慢移几乎不倾，快甩才猛涨 |
| `drag_tilt_max` | 45.0 | 倾角硬上限（度）|

⭐ 这四个参数（omega0 / zeta / drive / drive_exp）**是耦合的**，看公式推不出好看的手感。
所以 `run.py --tuner` 给了一个滑杆调试台，可以边拖边看、存预设、A/B 秒切 —— 别靠猜。

### 互动

| 字段 | 默认 | 说明 |
|---|---|---|
| `mood_max` | 100.0 | 好感度上限 |
| `mood_per_click` | 8.0 | 点一下加多少 |
| `mood_decay` | 1.2 | 每秒自然衰减 |
| `seek_cursor_mood` | 65.0 | 好感度高于这个值 → 会主动朝光标走 |
| `seek_chance` | 0.5 | 满足条件时"去找光标"的概率 |
| `arrive_eps` | 12.0 | 距目标多近算"到了"（px）|
| `pat_duration` | 1.2 | 被摸时播多久 `pat`（秒）|

## 最小可用包

只要一个动作也能跑起来：

```json
{
  "name": "mycat",
  "canvas": [512, 512],
  "anchor": [256, 512],
  "actions": { "idle": { "frames": 22, "fps": 10.0, "loop": "pingpong" } },
  "behaviour": {}
}
```

`behaviour` 缺失的字段全部有默认值（见 `core.Behaviour`），不用逐个填。

完整的字段清单可以照着 `packs/_template/pet.json` 抄。
