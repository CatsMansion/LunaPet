# 自研桌面宠物引擎 · 架构设计 v0.1

> 起因（2026-09-25）：DyberPet 作者限制我们用他的引擎上 Steam（他自己要上）。
> ⭐ 独立做引擎本来就在路线图上，这次提前，**而且我们比第一次做的时候懂得多得多。**

---

## 一、技术栈选择（这条决定 Steam 能不能上）

| 选项 | 优点 | 缺点 | 判断 |
|---|---|---|---|
| ⭐ **Python + PySide6** | ① **我们全部知识都在这**（DyberPet 就是这套）② **透明无边框置顶窗口已证明可行** ③ 开发最快 | 打包 ~150MB；性能一般 | ⭐ **v1 选它** |
| Electron | 跨平台，Web 技术 | ⛔ **Windows 上"透明 + 点击穿透"坑多**；体积更大 | 备选 |
| Rust + Tauri | 体积小、性能好 | 从零学，慢 | ⛔ 现阶段不划算 |
| **Godot** | ⭐ **Steamworks 原生集成**，做交互/小游戏顺手 | 要学 GDScript | ⭐ **将来迁壳的候选** |

### ⭐⭐ 关键决策：**把「逻辑」和「渲染」分开**

```
core/     纯逻辑，零 UI 依赖  ← 角色包格式 / 动作状态机 / 物理 / 边界
ui/       渲染与窗口          ← PySide6 实现（将来可换 Godot/Electron）
```

⭐ **理由**：今天踩的所有坑（循环周期、`frame_move`、屏幕限位、拖拽手感）**都是 core 层的事**。
拆干净了，**将来换壳只重写 ui/**，素材和参数一行不用改 ✅

---

## 二、⭐ 把今天学到的全部烤进设计（这是自研最大的价值）

| 今天踩的坑 | DyberPet 里的表现 | 我们的设计 |
|---|---|---|
| ⭐ **循环周期必须覆盖"两步"** | 只能靠 mod 作者自己试，`period 8~20` 写窄了永远搜不到 | **角色包 JSON 里声明 `cycle_frames`；加载时做一次剪影自检，周期不对就警告** |
| ⭐ **`frame_move` 靠猜** | 只有 `frame_move` 一个数字，没有推导依据 | **JSON 里给 `stride_px`（一圈走多远），引擎自己算每帧位移** ✅ 从根上消灭太空步 |
| ⛔ **屏幕限位按窗口中心** | 半个 sprite 能出屏（issue #103） | ⭐ **加载时算各动作 alpha 的并集 bbox，按"实际轮廓"限位** |
| ⛔ **主角色不能旋转** | 拖拽时竖直像挂着的 | ⭐ **核心层就支持旋转**（拖拽倾斜 + 惯性） |
| **帧间闪烁** | 无时域处理 | ⭐ **加载时可选做时域一致性检查** |
| **逐帧读盘** | — | **全动作预加载进内存**（142 帧 × 512² ≈ 数十 MB，可接受） |
| **行为不可控** | 状态逻辑埋在框架里 | **状态机显式声明在 JSON，可读可改** |

⭐⭐ **一句话：DyberPet 的坑我们一个都不重犯，因为那些坑是我们自己踩出来的。**

## 三、角色包格式（⭐ 兼容我们**已经做好的素材**）

```
res/role/<角色名>/
├── pet.json          角色定义（替代 pet_conf.json）
├── action.json       动作参数（替代 act_conf.json）
└── action/
    ├── idle_0.png ... idle_21.png
    ├── walk_0.png  ... walk_27.png
    └── ...
```

### `pet.json`

```json
{
  "name": "露娜",
  "scale": 1.0,
  "canvas": [512, 512],
  "anchor": [256, 512],          // 角色在画布里的"脚底中点"参考点
  "actions": {
    "idle":  { "frames": 22, "fps": 10, "loop": "pingpong" },
    "walk":  { "frames": 28, "fps": 12.5, "loop": "cycle",
               "cycle_frames": 28,        // ⭐ 一个完整步幅 = 两步
               "stride_px": 154,          // ⭐ 一圈走多远 → 引擎自己算每帧位移，永不太空步
               "mirrorable": true },      // 可由右向帧镜像出左向
    "fall":  { "frames": 14, "fps": 25, "loop": "once" },
    "land":  { "frames": 16, "fps": 25, "loop": "once" },
    "drag":  { "frames": 16, "fps": 12, "loop": "cycle" },
    "pat":   { "frames": 18, "fps": 12, "loop": "pingpong" }
  },
  "behaviour": {
    "idle_duration": [3, 8],       // 秒，随机
    "walk_weight": 0.6,
    "gravity": 1800,
    "drag_tilt_max": 12,
    "screen_margin": 0
  }
}
```

⭐ **注意 `stride_px` / `cycle_frames`** —— 这两个字段就是今天那两个坑的解药，
**DyberPet 里没有，我们这里是必填。**

## 四、v0.1 要做到什么（最小可跑）

- [x] 透明 / 无边框 / 置顶窗口
- [x] 加载角色包（`pet.json` + `action.json` + 帧）
- [x] **动作状态机**：idle → walk → idle，拖拽 → 松手 → 下落 → 落地 → idle
- [x] **拖拽物理**：跟随鼠标 + 惯性 + 重力 + 落地
- [x] **拖拽倾斜**（今天 issue #103 里想要的那条）
- [x] **屏幕限位按实际轮廓**（issue #103 想修的）
- [x] **走路位移由 `stride_px` 推出**（不靠手调 `frame_move`）
- [x] 托盘图标：显示/隐藏、退出
- [ ] ⏳ 多角色（v0.2）
- [ ] ⏳ 互动（摸摸 / 喂食）（v0.2）
- [ ] ⏳ Steamworks 集成（上架前）

## 五、⛔ 红线（沿用项目既有规矩）

## 六、实现顺序（每步都能跑）

```
① 骨架：透明窗口显示一张静态图           ← 先证明"能显示"
② 加载器：读角色包 + 播 idle             ← 证明"能动"
③ 状态机：idle/walk 切换 + 边界          ← 证明"会走"
④ 物理：拖拽 + 重力 + 落地               ← 证明"能拖"
⑤ 旋转：拖拽倾斜                          ← 今天的 issue #103 诉求
⑥ 打包：PyInstaller → 单文件 exe         ← 证明"能发"
```
